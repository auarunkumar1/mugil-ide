# Release Plan: v0.1.13 — OpenCode Free Tier & Cache Resilience

**Target Version**: `0.1.13`  
**Date**: September 2026  
**Status**: Ready for Release

---

## 1. Summary of Changes

This release resolves critical compatibility issues with OpenCode Zen free-tier models and fixes an unhandled crash in the Smart Cache engine when scanning session-backed cache directories.

---

## 2. Issues Addressed & Root Causes

### A. OpenCode 429 Too Many Requests (`FreeUsageLimitError`)
- **Problem**: In Mugil IDE, requests targeting OpenCode Zen free models failed with `HTTP 429 Too Many Requests` (`FreeUsageLimitError`) even with a valid OpenCode key, despite working in the official OpenCode IDE.
- **Root Cause**: Upstream OpenCode Zen proxy gates free model access on client fingerprinting (`User-Agent: opencode/<version>`). Requests missing this header or presenting third-party identifiers get rejected with anti-abuse 429 errors.
- **Resolution**:
  - Injected official `User-Agent: opencode/1.18.27` in `OpenCodeClient` (covering both Anthropic Messages wire format and OpenAI Chat Completions wire format) and in `models.ts` catalog discovery.
  - Added extensible `headers?: Record<string, string>` support to `OpenAiClientOptions` and `AnthropicClientOptions`.
  - Identified and verified operational free models (`nemotron-3.5-lightning-free`, `nemotron-3-ultra-free`) vs globally exhausted contributor models (`muse-spark-*`).

### B. Smart Cache Non-Prompt Session File Crash
- **Problem**: Running `mugil-ide run` failed with `TypeError: Cannot read properties of undefined (reading 'length')` at `SmartCache.partialLookup`.
- **Root Cause**: When session files (`last-session-*.json`) are co-located in `MUGIL_IDE_CACHE_DIR`, `this.backend.keys()` returned session keys. When parsed, `entry.prompt` was `undefined`, throwing on `.length`.
- **Resolution**: Added strict type check `if (!entry || typeof entry.prompt !== 'string') continue;` in `SmartCache.partialLookup`.
