# Mugil IDE v0.6.0 Release Plan

- **Status:** Approved for Implementation (Monolithic Release)
- **Date:** 2026-11-23
- **Release type:** Minor (`v0.6.0`)
- **Repository:** <https://github.com/auarunkumar1/mugil-ide>
- **License:** MIT
- **Release theme:** Provider Core v2 — correct OpenCode/OpenRouter behavior, token efficiency, local-AI parity, fail-closed secret boundary with non-blocking alerts, and two-phase width-aware terminal Markdown rendering.

---

## 1. Summary

`v0.6.0` ships as a **monolithic release** encompassing the entire Provider Core v2 refactor. The P1 provider fixes are front-loaded, the fail-closed security boundary lands before any new provider protocol code, and the larger provider refactor is protected by hermetic contract fixtures and the `MUGIL_IDE_PROVIDER_V2` feature flag.

The release has five core product goals:

1. **Provider correctness** — OpenCode Go, OpenCode pay-as-you-go, legacy Zen, and OpenRouter work predictably with accurate usage, limits, errors, and billing semantics.
2. **Fail-closed secret boundary & non-blocking alerts** — credentials and sensitive values are detected and vaulted into local-only placeholders (`[MUGIL_SECRET_TYPE_N]`). An alert banner informs the user immediately without pausing or aborting turns mid-flight. Cleartext secrets never leave the machine.
3. **Native protocol routing & reasoning continuity** — models route through their native API families (OpenAI Chat Completions, Anthropic Messages, and OpenAI Responses API), preserving reasoning blocks across multi-turn tool loops.
4. **Token efficiency & local-AI parity** — every turn reports real prompt, completion, reasoning, and cache tokens; prompt caching is preserved; and llama.cpp, Ollama, and LM Studio remain first-class citizens regression-tested alongside cloud providers.
5. **High-quality width-aware terminal Markdown rendering** — in-house GFM subset renderer supporting two-phase progressive table streaming, syntax-highlighted code blocks, OSC 8 links, blockquotes, and dynamic terminal resize awareness (`resize_agent`).

## 2. Locked Decisions

| Decision | Choice | Rationale |
|---|---|---|
| **Release cadence** | Monolithic `v0.6.0` | All milestones (M0–M7) ship together in a single release; feature flags (`MUGIL_IDE_PROVIDER_V2`) protect against regressions. |
| **Secret policy** | Vault-Tokenize & Alert (Non-blocking) | Secrets found in user prompts or tool outputs are vaulted as `[MUGIL_SECRET_TYPE_N]`; a non-blocking alert banner informs the user without interrupting tool loops. `OutboundGuard` fails closed only if raw plaintext escapes to a remote endpoint. |
| **Terminal table renderer** | Two-Phase Progressive Streamer | Buffer header, separator, and first 2 rows to compute column widths against live terminal width, then stream subsequent rows progressively with clean cell truncation (`…`). Eliminates stream freezing on large tables. |
| **Terminal resize plumbing** | Plumb `resize_agent` to `ReplIO` | Handle `resize_agent` websocket events in `server.ts` to keep `ReplIO.getColumns()` synced with the browser xterm geometry. |
| **Native protocol priority** | Native OpenCode protocols first | Implement native Chat, Messages, and Responses adapters for OpenCode Go and Zen before extending OpenRouter. |
| **Reasoning continuity** | Assistant block replay | Replay assistant reasoning blocks across tool loops so reasoning models maintain contextual coherence. |
| **OpenRouter scope** | Errors, usage, reasoning, attribution | 200-body errors, mid-stream SSE errors, `Retry-After`, reasoning params, and GitHub attribution URL; structured outputs and `:online` deferred to `v0.7.0`. |
| **Local endpoints** | Loopback always local; LAN opt-in | `localhost`, `127.0.0.1`, `::1`, and `0.0.0.0` are local by default. Private RFC1918 LAN addresses are local when `MUGIL_IDE_LOCAL_ENDPOINTS=private-lan`. |
| **Code highlighting** | Common-language in-house highlighter | Highlighting for TS/JS, JSON, Python, Shell, and Diff with plain monospace fallback; zero runtime dependencies. |
| **Roadmap deferrals** | Deferred to `v0.7.0` | Voice input, autonomous Git PR automation, and team collaboration hub move to `v0.7.0`. |

## 3. Current Findings & Codebase Reality

Audit verified against codebase state (v0.5.3, 718 passing tests):

### 3.1 OpenCode
- **Base URL rewrite:** `packages/core/src/config.ts:841` rewrites explicit `OPENCODE_BASE_URL=https://opencode.ai/zen/v1` to `https://opencode.ai/inference/go`.
- **Client impersonation:** `packages/core/src/modules/handoff/openCode.ts:37` hardcodes `OPENCODE_USER_AGENT = 'opencode/1.18.27'`.
- **Quota retry storms:** Go quota `429` is treated as generic retryable error, attempting every fallback model against an exhausted allowance.
- **Probe overhead:** `detectOpenCodeSubscription` sends a full completion request to `beam-free` on every probe instead of querying `GET /inference/go/v1/usage`.
- **Ignored billing fields:** Response fields (`cost`, `billing_source`, `allowance`, `opencode.tokens`) are unparsed; UI defaults to list-price spend.
- **Error mapping gaps:** Documented `MissingSessionID`, `AuthError`, `EntitlementError`, and region restrictions rely on ad-hoc string matching.
- **Missing Responses API:** Models requiring the Responses API (`/responses` or `/openai/v1/responses`) fail or rely on Console translation.
- **Session generation:** `x-opencode-session` is generated per client instance rather than per conversation/session.
- **Hardcoded model count:** `packages/cli/src/server/server.ts:1303` displays hardcoded `'OpenCode Go (Active Subscription · 31 Models)'`.
- **Free model normalization:** `deepseek-v4.1-flash-free` and `mimo-v2.6-flash-free` are normalized to paid models, consuming credits unexpectedly.

### 3.2 OpenRouter
- **200-body errors:** `provider.ts:446-490` treats 200 HTTP responses containing top-level `error` or `choices[0].error` as success with empty text.
- **Mid-stream errors:** SSE `event: error` and `finish_reason: "error"` do not throw.
- **Retry-After ignored:** `Retry-After` headers on 429, 503, and 402 are dropped.
- **Missing reasoning:** `reasoning` / `reasoning_effort` parameters are not sent.
- **Localhost attribution:** App attribution defaults to `https://mugil-ide.local` instead of the GitHub repository URL.
- **Non-streaming wire pollution:** `UnifiedWireClient.buildBody` adds `stream_options` to non-streaming requests.

### 3.3 Security & Secret Boundary
- **Scanner omissions:** `secretScanner.ts` lacks patterns for OpenCode keys (`oc_sk_...`), GitLab PATs, GitHub fine-grained PATs, and JWTs.
- **Regex logic bug:** Line 104 `reject: notPlaceholder` has an inverted predicate evaluation.
- **Unprotected webhooks:** `pipeline.ts:184` dispatches `turn.started` with raw prompt before tokenization; line 508 dispatches `tool.executed` with raw arguments.
- **No fail-closed outbound guard:** Outbound payloads lack centralized verification before leaving the machine.
- **Missing known-secret registry:** Configured provider keys from environment variables are not registered as exact known secrets.

### 3.4 Terminal Rendering
- **Feature gaps:** `packages/cli/src/terminal/ansi.ts` (`StreamMarkdown`) lacks support for tables, nested lists, task lists, blockquotes, strikethrough, links, and width-aware wrapping.
- **Dropped resize events:** `packages/cli/src/server/html.ts:4389` sends `resize_agent` over websocket, but `server.ts:2753` drops it, leaving the renderer unaware of terminal geometry.
- **Chunk fragmentation:** Partial multi-character tokens (backticks, asterisks, brackets) can split across stream chunks and leak raw syntax.

### 6.1 Plan Detection and Endpoint Resolution
- Add `detectOpenCodePlan(apiKey: string)` querying `GET /inference/go/v1/usage`:
  - `200` $\rightarrow$ OpenCode Go.
  - `402` / `403` $\rightarrow$ Pay-as-you-go.
  - `401` $\rightarrow$ Invalid key.
  - Offline/mock $\rightarrow$ Non-blocking fallback.
- Cache plan detection in memory keyed by `sha256(apiKey)`.
- Resolution precedence:
  1. Explicit `OPENCODE_BASE_URL` always wins.
  2. Detected Go $\rightarrow$ `https://opencode.ai/inference/go`.
  3. Detected pay-as-you-go $\rightarrow$ `https://opencode.ai/inference`.
- Delete the `zen/v1` $\rightarrow$ Go rewrite in `packages/core/src/config.ts:841`.
- Implement bidirectional fallback for completions and model discovery.
- Replace hardcoded `'OpenCode Go (Active Subscription · 31 Models)'` with dynamic catalog count.

### 6.2 Usage, Quota, and Billing
- Implement `fetchOpenCodeUsage()` parsing allowance meters and reset timestamps.
- Parse `usage.opencode` and `usage.cost` from JSON and streaming events.
- Treat Go quota `429` as non-retryable; fail fast with clear reset instructions.
- Show allowance consumption for Go; show dollar spend for pay-as-you-go/BYOK.
- Apply pricing multipliers and overrides.

### 6.3 Errors and Sessions
- Map structured OpenCode error codes: `MissingSessionID`, `AuthError`, `EntitlementError`, region restrictions, and quota limits.
- Detect 200-body errors and mid-stream SSE `error` events.
- Persist `x-opencode-session` per conversation/session across restarts and client instances.

### 6.4 Catalog Cleanup

### Exit Criteria

- Quota 429 fails fast with reset time without exhausting fallback chains.

## 7. Phase 2 — Secret Boundary & Non-Blocking User Alerts

**Goal:** Guarantee that sensitive credentials never leave the machine in cleartext, while maintaining uninterrupted tool loops and clear user visibility.

### 7.1 Outbound Guard
- Implement `packages/core/src/modules/security/outboundGuard.ts`:
  - Classify destinations as `loopback`, `private-lan`, or `remote`.
  - Recursively sanitize messages, tool arguments, headers, and metadata.
  - Fail closed with `SecretLeakError` if un-tokenized credentials survive to a remote destination.
  - Permit provider API keys exclusively in their own `Authorization` headers.

### 7.2 Exact Known-Secret Registry
- At engine startup, register exact values of all configured provider keys:
  `OPENCODE_API_KEY`, `OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `VERCEL_API_KEY`, `CLOUDFLARE_API_KEY`, `TOGETHER_API_KEY`, and webhook secrets.
- Register keys directly into `SecretVault.registerKnownSecret()` to ensure exact substring matching before regex execution.

### 7.3 Scanner Expansion
- Add patterns for:
  - `\boc_sk_[A-Za-z0-9_-]{20,}\b` (OpenCode)
  - `\bglpat-[A-Za-z0-9_-]{20,}\b` (GitLab PAT)
  - `\bgithub_pat_[A-Za-z0-9_]{22,}\b` (GitHub fine-grained PAT)
  - `\beyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\b` (JWT)
  - Secret URL query parameters (`token=`, `api_key=`, `access_token=`, `key=`, `sig=`).
  - Common AI provider keys (DeepSeek, Groq, xAI, Moonshot, MiniMax).
- Fix logic inversion in `secretScanner.ts:104`.

### 7.4 Non-Blocking User Alerting Workflow
- When a secret is vaulted during prompt ingestion or tool output processing:
  1. Secret value is stored in `SecretVault` memory and replaced with `[MUGIL_SECRET_TYPE_N]`.
  2. Emit an `onSecretDiscovered` event.
  3. REPL and Web UI display a prominent warning banner:
     ```
     ⚠️ [Secret Protected]: Sensitive credential detected and vaulted (TYPE).
     Opaque token substituted; plaintext will not leave this machine.
     ```
  4. Execution **continues uninterrupted** (no mid-turn pauses).
  5. Local tools (e.g. `run_command`) resolve tokens locally; remote models receive only placeholders.

### 7.5 Webhook and Outbound Protection
- Sanitize payloads in `packages/core/src/modules/webhooks.ts` (`fireWebhooks`) before dispatch.
- Ensure `turn.started` and `tool.executed` receive tokenized content.

### Exit Criteria
- Detected secrets in prompts or tool outputs are vaulted and alerted without halting turns.
- Remote endpoints reject cleartext secrets with `SecretLeakError`.
- Webhooks, logs, sessions, and WebSocket frames contain zero raw credentials.

## 11. Phase 6 — Width-Aware Terminal Markdown & ANSI Renderer

**Goal:** Deliver clean, high-performance terminal rendering in Web xterm and CLI REPL with dynamic width support.

### 11.1 Module Structure
Add `packages/cli/src/terminal/markdown/`:
- `tokenize.ts`: Incremental GFM block tokenizer.
- `inline.ts`: Inline formatting (bold, italic, strikethrough, inline code, OSC 8 links).
- `table.ts`: Two-phase progressive table streaming.
- `code.ts`: Common language syntax highlighter (TS/JS, Python, JSON, Shell, Diff).
- `render.ts`: Block to ANSI string renderer.
- `stream.ts`: Width-aware streaming processor with chunk boundary safety.
- `index.ts`: Unified module exports.

### 11.2 Two-Phase Progressive Table Streaming
1. **Phase 1 (Buffer & Measure):** Buffer table header row, delimiter row, and first 2 data rows to compute column widths against available terminal columns.
2. **Phase 2 (Progressive Stream):** Once column widths are locked, format and emit subsequent rows line-by-line as they arrive from the model.
3. Truncate overflowing cell contents with ellipsis `…` to guarantee box alignment.

### 11.3 Dynamic Resize Plumbing
- In `packages/cli/src/server/server.ts`, add handler for `resize_agent`:
  ```typescript
  } else if (msg.type === 'resize_agent') {
    agentRepl?.setColumns(Number(msg.cols));
  }
  ```
- Plumb columns through `ReplIO.getColumns()` into `StreamMarkdown`.

### 11.4 In-House Syntax Highlighting
- Implement token-based highlighting for:
  - TypeScript / JavaScript (keywords, strings, numbers, comments)
  - Python (defs, keywords, strings, decorators)
  - Shell (commands, flags, strings, variables)
  - JSON (keys, values, numbers, booleans)
  - Unified Diff (`+` green, `-` red, `@@` cyan)
- Fallback to clean monospace ANSI styling for unrecognized languages.

### Exit Criteria
- Markdown tables render cleanly without stream stalling.
- Dynamic terminal resize updates column layouts correctly.
- Single-char streaming output is identical to bulk string formatting.
- Zero ANSI escape code leakage.
